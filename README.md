# BMS SOC 离线仿真实验室（Mac M4 版）

> 研究原型 v0.1，2026-10。**不是量产车BMS或安全验证软件**，没有在你的真实整车数据上验证。

## 0. 这套工具能做什么？

- 从**本机或移动硬盘**读取 CSV / XLSX / XLSM / Parquet 的 BMS 采样数据。Mac 移动硬盘路径一般为 `/Volumes/硬盘名称/...`。
- 自动猜测时间、总电流、单体电压、BMS SOC等列名；可手动映射，并选择1～16节电芯逐个分析。
- 以1Hz为基础运行**安时积分**、**一阶RC+SOC-EKF**、**双EKF研究原型**，分别输出 SOC 时间序列。
- 参数EKF尝试在线辨识 **OCV、R0、R1、τ（=R1×C1）**。极化电压 `Up` 作为内部状态；5类工况使用不同Q及测量更新权限。
- 在线OCV**只记录不回写**，用于未来分析OCV老化/重构；SOC滤波依然读取匹配的**离线OCV-SOC表**。
- 与**独立参考SOC**、原车BMS显示SOC或用户双锚点推算的参考值比较。输出RMSE、MAE、最大误差、平均偏差、曲线、参数、残差和配置。
- 本地网页应用运行在 `http://127.0.0.1:8501`，数据不经过ChatGPT服务器；**首次安装依赖需要网络**。

**没有实现**：CAN原始DBC解码、多文件自动拼接、在线OCV表更新、老化SOH联合估算、量产安全保护、经验证的最优Q/P/R。这些是后续研发阶段。

## 1. Mac 安装步骤（只需要一次）

1. 将整个 `BMS_SOC_Lab` 文件夹解压到 Mac 本地硬盘，例如 `~/Documents/BMS_SOC_Lab/`。**不需要把移动硬盘数据复制进项目**。
2. 安装 **Python 3.10或更高**，推荐 Python 3.12；如果已安装，跳过。
3. 双击 `start.command`。如Mac阻止打开，在Finder中右键该文件选择“打开”。
4. 首次会自动创建 `.venv` 并下载依赖，之后浏览器访问 `http://127.0.0.1:8501`。
5. 以后的使用只需双击 `start.command`。完成后关闭终端窗口即可退出本地服务。

如果双击报权限错误，打开Mac终端运行：

```bash
cd ~/Documents/BMS_SOC_Lab
chmod +x start.command
./start.command
```

**无桌面IDE要求**，仅首次依赖安装需一个终端窗口。

## 2. 先使用合成数据自检

项目自带：

- `demo/synthetic_vehicle_1Hz.csv`：5400行1Hz的人工合成电芯数据，包含合成的参考真实SOC；该数据并非从任何实车采集。
- `demo/synthetic_ocv_table.csv`：与合成数据对应的OCV-SOC表。**绝不可作为真实电池的通用OCV表**。

左侧选择默认 `demo/` 文件，选择列后点击“运行离线仿真并生成报告”。

**预期现象**：安时积分因为初始SOC和容量设错，会有误差；单EKF能利用已知的合成OCV曲线纠偏；双EKF研究原型的在线参数因辨识不足**有可能失准或发散**。这正是我们需要在真实数据里诊断的失效边界，不能把演示结果宣称为精度指标。

## 3. 读取你的移动硬盘

将硬盘连接Mac、在Finder确认已挂载，复制文件绝对路径：

```text
/Volumes/你的硬盘名称/车辆数据/2026-10-26/drive.csv
```

把路径填入网页的“原始数据来源 → 完整路径”。也可输入**直接包含数据文件的文件夹路径**，再选择文件；或者使用网页文件选择器。

首批建议只选：

- 一节健康正常的电芯；
- 一节疑似异常电芯（若有）；
- 包总电流（放电方向默认**正值**，如原始数据为负，请勾选反向）；
- 时间列（实际每行间隔约1秒）；
- 一个参考SOC列（如有）。

### 推荐的CSV格式

```csv
time_s,pack_current_a,cell_01_v,cell_02_v,temperature_c,reference_soc_pct,bms_soc_pct
0,20,3.330,3.331,26.1,85.00,84.5
1,30,3.322,3.323,26.1,84.99,84.5
2,0,3.348,3.350,26.1,84.98,84.5
```

数据可用 mV 或 V（程序会对疑似mV列自动除以1000）。时间可以是秒数或可识别的日期字符串。对于毫秒时间戳，建议先统一转成秒。

### 必需的离线OCV表

文件至少包含两列 `soc_pct,ocv_v`，覆盖0%～100%且随SOC非递减。**请采用你电芯对应材料、温度、放电/静置策略的已标定曲线**，不能用示例表替代。

## 4. “参考SOC”究竟指什么？

| 来源 | 软件中的定位 | 能否声称是真实RMSE？ |
|---|---|---|
| 已独立高精度标定的参考SOC | 主要评价依据 | 在参考方法误差得到控制时可以 |
| 原车BMS显示SOC | 只代表与原车算法的一致性 | 不可以 |
| 已知起止SOC锚点+积分重构 | 近似参考曲线；用于调试 | 不能把锚点假设当作真值 |
| 无参考数据 | 仅输出SOC轨迹及参数 | 不计算RMSE |

软件中的 `RMSE` 单位为 **SOC百分点（pp）**，不是容量相对百分比。

## 5. 与你原算法如何对应？

当前实现：

1. **参数滤波器**：内部状态 `[OCV, R0, R1, tau, Up]`，其中前4项为在线参数，`Up` 是RC动态极化状态。根据工况切换参数Q和门控。
2. **SOC滤波器**：状态 `[SOC, Up]`，始终使用原始离线OCV表，内阻和极化参数可取自第1步。
3. **比较模块**：安时积分 vs 固定参数SOC-EKF vs 研究版双EKF，记录误差与异常。

当前双EKF不是2021年你的原始模型复刻。它没有精确复现你当年的状态方程、参数交叉相关性与异常降级策略。不同KF共享电压观测，也存在相关性问题。**必须将当前研究版当作可替换的实验基线，不应直接嵌入量产MCU。**

## 6. Q、P、R在哪修改？

`config.json`。参数EKF：

- `initial_sigma`：参数初始标准差，平方为P0对角初值；
- `sigma_change_over_100s`：假设参数在100秒随机游走的标准差，平方除100得到每秒基础Q；
- `mode_q_multipliers`：工况乘数，可以在网页“高级选项”里修改；
- `mode_update_mask`：控制哪些参数允许更新；
- `sigma_measurement_mv`：R的平方根（mV）。

SOC-EKF的P/Q/R对应位于 `soc_filter`，分别以初始标准差、每步标准差、观测误差标准差表达。

所有默认值为**仿真用假设值**，不是基于你的电芯标定的结果。先用少量数据做敏感性分析，再给出值得投入计算资源的Q配置。

## 7. 命令行批量运行（可选）

```bash
.venv/bin/python cli.py \
  --input demo/synthetic_vehicle_1Hz.csv \
  --ocv demo/synthetic_ocv_table.csv \
  --output-dir outputs/cli_test
```

可以 `--capacity-ah 90 --initial-soc-pct 94 --invert-current --ref-col reference_soc_pct` 等方式改变参数。

输出在 `outputs/cli_test/`：`REPORT.md`、`timeseries_results.csv`、`soc_metrics.csv`、`SOC_cell_01_v.png`、`run_config.json`。

## 8. 安全与局限

- 1Hz数据不能直接还原亚秒级R0瞬态；条件检测仅是近似。
- **电压拟合好≠OCV辨识正确≠SOC估算准确**；必须验证OCV/R0/R1的耦合与可观测性。
- 工况门控/协方差尚未量产标定，双EKF发生较大误差是预期风险之一。
- 当前估算采用单体电压＋包电流，不包含单体并联支路电流差、均衡、热耦合和完整迟滞模型。
- 对车包SOC采用单节电芯曲线估计，仅是对比实验，不等同完整pack SOC算法。
- 禁止将该原型连接车辆控制器或用于实时车辆安全决策。
