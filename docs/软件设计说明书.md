# BMS SOC Lab 软件设计说明书

**版本：** V0.2（Codex交接基线）  
**日期：** 2026-10-26  
**项目性质：** 本地离线研究仿真工具 / 非量产功能安全软件  
**目标运行环境：** macOS（Apple Silicon / M4），Python 3.10+，本地浏览器  
**状态定义：** 已实现 / 待标定 / 拟开发严格分开

## 1. 项目概述

### 1.1 背景

本项目起源于针对LFP平台期SOC修正、三元锂实车老化适应及在线OCV辨识的研究。用户曾在真实车辆上研究一阶RC + 双卡尔曼滤波（Dual EKF）：第一组滤波器在线辨识OCV、R0、R1、C1；第二组滤波器使用**离线初始OCV-SOC查表**进行SOC估算，允许读取第一组的在线阻抗参数，但**在线OCV暂时不直接参与SOC查表**，以避免不可信OCV破坏主估算结果。

研究关键问题包括：①参数之间的可辨识性与电压残差错误归因；②依据电流工况切换Q矩阵；③老化OCV片段的坐标锚定与重构；④初始SOC错误、SOH失配情况下的收敛和失效边界；⑤在资源受限MCU上执行时的数值安全与最坏运行时间。

### 1.2 目标与非目标

**目标：** 自动读取1Hz整车BMS数据（包电流、16串单体电压、电芯温度、工况状态、可选参考SOC），运行安时积分、单EKF和双EKF研究基线，输出逐秒轨迹、OCV与阻抗辨识、创新残差、SOC RMSE/MAE/最大误差及可追溯报告；支持Mac本地移动硬盘文件路径。

**非目标：** 当前不提供量产BMS、车载在线控制、ASIL论证或无依据的精度保证；没有真实16串三星数据；没有对2021年原算法精确复刻；没有验证在线OCV曲线自动回写的安全性。

## 3. 软件总体架构

```text
本机移动硬盘 / CSV·Excel·Parquet / （后续MAT）
                  │
           数据读取与标准化
       时间 / 电流符号 / 单位 / 缺失
                  │
   ┌──────────────┼─────────────────────┐
   │              │                     │
安时积分       一阶RC SOC-EKF       参数EKF (OCV/R0/R1/tau + Up)
   │              │                     │
   │              │              五工况识别 → Q切换与更新门控
   │              │                     │
   │              └──────────在线R0/R1/tau输入
   │                                    │
   └──────────────┬─────────────────────┘
                  │
     SOC轨迹 / OCV / 阻抗 / 残差 / 模式
                  │
       参考SOC可信度分类与误差计算
                  │
  报告输出 / 数据可视化 / CSV / PNG / JSON
```

**依赖关系：** `app.py` 为本地Streamlit界面；`cli.py` 为批处理入口；`bmslab/engine.py` 为数据和算法；`bmslab/reports.py` 生成报告；`data_sources/samsung30t_pipeline.py` 处理三星实验数据；`config.json` 管理参数；`tests/` 执行回归测试。

**运行边界：** 默认离线计算，文件读取来自本机或挂载的移动硬盘；首次安装Python依赖需联网。不要主动上传用户车辆明细数据到网络服务。

## 4. 输入、数据契约及质量控制

### 4.1 标准输入

| 列名 | 单位 / 定义 | 必需 |
|---|---|---|
| `time_s` | 严格递增秒数（推荐1Hz，可保留真实dt） | 是 |
| `pack_current_a` | 总电流，标准化为放电正、充电负 | 是 |
| `cell_01_v ... cell_16_v` | 各串单体电压，V | 至少一节；16串优先 |
| `temperature_c` | 电芯温度，℃（未来扩展多传感器） | 建议 |
| `vehicle_state` | 行驶、充电、静置等工况标签 | 可选 |
| `reference_soc_pct` | 独立参考SOC，0~100百分点 | 可选 |
| `bms_soc_pct` | 原车BMS估算SOC，仅作对照 | 可选 |

**当前代码与目标差异：** 时间、电流、电压和参考SOC具备基本导入；温度与行车状态尚未完整进入参数KF状态与工况分类逻辑；16串批量性能未经压力测试。必须在报告中保留源文件哈希、原始列映射、电流符号、容量、温度有效性、OCV表来源与数据清洗警告。

### 4.2 数据验证规则

加载时检查时间重复/逆序、间隔异常、单位错配、单体电压缺测与异常跳变、电流极性、长段静置、传感器饱和、跨片段拼接；不允许静默插值超过设定阈值的大断点。对每节电芯独立统计缺失率、超限点及覆盖时间。数据质量不合格时允许仅生成诊断报告而不输出“通过验证”结论。

## 5. 电池模型与算法定义

### 5.1 一阶RC放电模型

取放电电流为正：

```text
Vt(k) = OCV(z(k)) - I(k)*R0(k) - Up(k)
Up(k+1) = exp(-dt/tau)*Up(k) + [1-exp(-dt/tau)]*I(k)*R1(k)
tau = R1*C1
z(k+1) = z(k) - I(k)*dt/(3600*Qavailable)
```

注意单位：当前`engine.py`内部用OCV/极化`mV`、R0/R1用`mΩ`、τ用`s`、SOC用0~1，输出电压换算成V；不能直接将SI制参数矩阵Q复制到本单位制实现。对于温度、SOH、迟滞与复杂极化，当前一阶RC仅为研究近似。

### 5.2 双KF结构

**参数滤波器：** 内部状态 `[OCV_mV, R0_mOhm, R1_mOhm, tau_s, Up_mV]`。OCV、R0、R1、τ按工况选择是否更新，Up按模型动态传播并视模式参与测量更新。注意这五个状态共享**一个端电压测量**，参数耦合及交叉相关性可能导致虚假辨识；现有选择性截断Kalman增益方案需要专门检验协方差一致性。

**SOC滤波器：** 内部状态`[z, Up_mV]`，使用离线OCV-SOC曲线计算预测电压、OCV斜率和测量雅可比。双KF方案只传入前级辨识的R0、R1、τ；在线OCV原值仅作为诊断数据保存。两个滤波器使用同一电压观测，尚未严格处理共享观测带来的相关性，应在文档和精度结论中揭示。

### 5.3 五工况Q与门控

| 工况代码 | 触发逻辑（初版） | 主要更新意图 | OCV/R0/R1/τ 初始Q乘数 |
|---|---|---|---|
| `step` | 相邻电流变化超过`max(5A,0.1C)` | 优先R0 | 0.01 / 20 / 0.1 / 0.1 |
| `polarization` | 最近电流阶跃后60秒内 | 优先R1和τ | 0.05 / 0.1 / 10 / 10 |
| `steady` | 非静置、非阶跃窗口 | 保守更新/冻结 | 0.1 / 0.1 / 0.1 / 0.1 |
| `rest_early` | 电流绝对值低于静置阈值且未满300秒 | 优先极化恢复 | 0.05 / 0.01 / 5 / 5 |
| `rest_late` | 连续静置至少300秒 | 尝试OCV更新 | 5 / 0.01 / 0.01 / 0.01 |

上述值直接来自`config.json`，**仅为合成数据起始权重，没有经过任何电芯实测标定**。`mode_update_mask`使`step`仅更新R0，`polarization`仅更新R1、τ，`steady`冻结四参数，`rest_early`更新R1、τ，`rest_late`仅更新OCV；Up的内部处理另有控制。高Q表示允许更快随机游走，并不等于具有更强可辨识性。

### 5.4 Q、P0、R初值与离线标定

参数随时间按随机游走建模。若假定100秒的参数变化标准差为`delta_100s`，采样1秒，则基础`q_i = delta_100s^2 / 100`；乘上工况倍率构成Q。当前默认假设的100秒标准差依次为：OCV=2mV、R0=0.05mΩ、R1=0.05mΩ、τ=4s，对应Q基础对角线`[0.04,0.000025,0.000025,0.16]`（各参数各自单位的平方/每秒）。

初始参数标准差为12mV、0.30mΩ、0.20mΩ、20s；`P0`对应对角线`[144,0.09,0.04,400]`，另加极化状态初始方差`15^2=225mV²`。参数KF默认`R=(5mV)^2=25mV²`；SOC KF默认`R=(7mV)^2=49mV²`。**这是软件默认值的解释，不是噪声实测值**。后续需使用噪声统计、独立HPPC和参数波动估计量化，并在未参与标定的数据上复核。

### 5.5 SOC参考值与比较

优先采用独立容量标定及准确边界锚点生成的参考SOC。原车BMS显示SOC仅供一致性比较，不能直接叫真实SOC。双锚点容量代理：`Q_est = ΔAh / [(z_start-z_end)/100]`，中间`z(t)=z_start-100ΔAh(t)/Q_est`；当终点锚点不独立、容量随温度/倍率波动、或者整段存在未知充放电间隔时，必须降低其参考等级。输出RMSE/MAE/MaxAE均用SOC百分点pp。

## 6. 在线OCV重构（下一阶段，尚未实现）

保留离线原表：第一KF产出带质量评分的`{time, online_OCV, temperature, current_mode, covariance, R0,R1,tau}`，仅记录不回写。通过可靠满电锚点及累计Ah得到相对放电轨迹；当低SOC端经独立验证后建立第二锚点，用容量伸缩把`OCV(ΔAh)`映射为`OCV(z)`。支持跨行程局部片段拼接与不同SOC区间的可信度。绝不能把在线OCV偏移直接解释为电池真实老化：必须排除阻抗/极化/迟滞耦合；新曲线需在留出工况、温度及SOH上独立验证后才可实验性切换。

## 7. 数据和实验输出

每次实验固定输出`run_config.json`、`timeseries_results.csv`、`soc_metrics.csv`（有合格参考时）、`REPORT.md`、`SOC_*.png`及可选`OCV_PARAMETER_DIAGNOSTICS.png`。新增字段建议：`source_sha256`、`reference_class`、`initial_soc_provenance`、`param_update_count_by_mode`、`q_schedule_id`、`innovation_whiteness`、`runtime_ms`、`invalid_samples`、`ocv_validity_score`。报告必须明确：哪一个指标基于真实独立参考，哪一个仅基于代理参考。

## 8. 测试与风险控制

| 风险 | 需要新增的测试/保护 |
|---|---|
| OCV-R0-R1耦合 | 对同一时段多倍率复测、参数相关性与局部信息矩阵；恒流和无静置时禁宣称OCV可辨识 |
| KF参数贴边/漂移 | R0/R1/τ物理边界、创新门限、协方差对称与半正定检测、异常冻结并退回离线值 |
| 参数KF共享观测 | 检查双KF协方差一致性；对比固定参数EKF，避免双重利用同一电压导致过度自信 |
| 1Hz瞬态丢失 | 不把相邻1秒采样的ΔV/ΔI解释为真实瞬时R0；标定需要高频HPPC对照 |
| 曲线误更新 | 版本化保存旧表、新表先离线A/B验证，不合格可回滚 |
| 运行时可靠性 | 24小时×16串回放、内存峰值、异常输入、时间超限、NaN/Inf与中断恢复测试 |
| 参考SOC错误 | 标签化：独立真值 / 双锚点代理 / 原车BMS显示；分开计算与展示 |

**拟议验收门槛（未来指标，不是已经达标）：** 24小时×16串全流程无NaN/死循环；在定义良好的留出测试集上量化OCV相对于独立静置/低倍率参考的偏差及其置信区间；报告SOC RMSE/MaxAE与收敛时间，按工况、温度、SOH分层。任何具体精度阈值必须在采集参考数据后由项目负责人批准。

## 9. 三星INR21700-30T真实数据专项

**来源：** McMaster University公开三星30T数据集：`https://data.mendeley.com/datasets/9xyvy2njj3/2`，DOI `10.17632/9xyvy2njj3.2`。本交接包**不含真实下载的MAT原始文件**；`tests/tmp_30t_format`若存在是**合成格式自检**，不可作为实测结论。建议两类同温度文件：25℃ `C20DisCh`（只能形成准OCV，不是完整静置平衡OCV）与25℃ `Mixed/UDDS`（需核验总时长≥3600秒及有效放电时间）。

批处理入口：`python data_sources/samsung30t_pipeline.py --data datasets/30t_measured --output outputs/samsung30t_validation`。必须先记录真实文件路径、大小和SHA256，再报告在线OCV更新次数、参数贴边、逐秒R0/R1/τ、新息统计以及相对于准OCV的偏差。仅准OCV + 假定满电的Ah参考，不能称作绝对OCV或SOC真值验证。

## 11. Codex交接准则与已知缺陷

**必须保留的研究原则：** 在线OCV与SOC主估算解耦；五工况Q离线标定；错误初始SOC和SOH失配为关键验收场景；不存在独立参考SOC就不宣称RMSE；未找到三星MAT文件就不要冒充已验证。

**优先检查的实现细节：** `run_parameter_ekf`只对K做选择性掩码，是否保留正确协方差一致性；`classify_modes`对静置中阶跃先后判定的影响；SOC状态P如何在跨采样间隔中调整；参数滤波器的OCV是否吸收极化偏差；代码是否有参数安全的只读诊断；`samsung30t_pipeline`的参考SOC来自假定初始100%与C/20容量而非独立真值；温度/行车状态尚未参与Q切换；自动解析外部ZIP时应继续加强归档文件安全验证。
